# 中国发明专利第二次审查意见通知书撰写技能

## 概述

本技能规范第二次审查意见通知书（二通）的撰写流程，涵盖：
- 申请人意见总结与要点提取
- 逐条答复申请人意见
- 在一通基础上修改创造性评述
- 二通特有的格式要求

二通与一通的核心差异：
1. **多了"答复申请人意见"部分**：需逐条回应申请人的每一个论点
2. **创造性评述需调整**：权利要求编号和内容可能因申请人修改而变化
3. **开头格式不同**：使用二通专用开头模板

## 创造性评述格式来源（重要）

二通中「**二、创造性评述**」部分的撰写格式，按以下优先级确定：

1. **首选（默认）**：审查搭档中「**通知书撰写辅助**」提示词（**2026年10月版本**）所规定的权利要求评述格式规范，包括但不限于：
   - 三步法评述结构：最接近的现有技术 → 区别特征 → 实际解决的技术问题 → 技术启示 → 显而易见结论；
   - 特征比对采用「（即……）」括注，括注内引用本申请权利要求原文并逐字一致；
   - 法律条款采用数字式表述：专利法第22条第2款、专利法第22条第3款、专利法第33条；
   - 装置／介质／设备／程序产品权利要求采用引用方法权利要求的评述方式；
   - 编号与权利要求号一一对应，每条意见以编号结论句单独成段开头；
   - 结尾段使用标准语段。
2. **次选**：用户提供的**上一次／前一次审查意见通知书**。当用户明确说明沿用该通知书的评述格式时，以其实际格式为准（包括段落组织、特征比对写法、法条表述与结尾语段）。
3. 上述两者不一致时，以用户本次明确说明的要求为准；用户未说明时，默认采用第 1 项。

## 前置条件

撰写二通前，必须准备好以下材料：
1. 一通原文（含创造性评述全文）
2. 申请人修改后的权利要求书
3. 申请人意见陈述书
4. 本申请原始说明书
5. 一通使用的对比文件（D1、D2等）

说明：第 1、5 项是答复的**默认证据基础**；检索不是必需步骤，只有在「检索判定」认定需要时才补充。

## 检索判定（默认不检索）

**本提示词默认不进行任何检索。** 答复所需证据以用户提供的材料为限：

1. 前次审查意见通知书及其引用的全部对比文件（D1、D2…）；
2. 本申请文件（权利要求书、说明书、摘要）；
3. 申请人意见陈述书及修改文本；
4. 前次通知书已引用的公知常识证据（教科书、工具书、标准）。

### 判定要求（撰写答复前必须完成）

先判断本案是否需要补充检索，并在答复正文之前明确输出一行结论：

- `检索判定：不检索`（默认）——依据现有证据（D1、D2…）与说明书原文答复；
- `检索判定：需补充检索`——必须同时写明：①缺口所在（哪项权利要求的哪个特征）；
  ②拟检索方向；③"是否执行，待用户确认"。

### 默认不检索的情形（满足任一即不检索）

| 情形 | 说明 |
|---|---|
| 申请人仅陈述意见、未修改权利要求 | 直接针对原证据逐条答复 |
| 修改仅为删除权项、合并从属权项、适应性修改编号/引用关系 | 未引入原权利要求未包含的技术特征 |
| 争议可通过引用说明书原文、对比文件原文、《审查指南》条款解决 | 以原文比对为主 |
| 仅涉及公知常识认定 | 用教科书/工具书/标准（用户提供或本领域通用）说明 |
| 用户未提出检索要求 | 一律按不检索处理 |

### 需要补充检索的情形（须"存在证据缺口"且"用户明确同意"）

1. 申请人修改后引入前次通知书未评述、且原对比文件未涉及的新技术特征，原证据无法覆盖；
2. 申请人提交了新的反证、实验数据或对比文件，需核实其公开内容或公开日；
3. 前次通知书引用的证据本身不可用（公开日不早于申请日/优先权日、文本无法对应、对比文件缺失）；
4. 用户明确要求补充检索（如另找更合适的 D1、补充创造性评述证据）。

出现上述情形时：**先说明理由并向用户确认，不得自行检索**。
仅当用户回复同意，或用户本条消息已明确要求检索时，才进入"补充检索执行要求"。

### 补充检索执行要求（仅在获准后适用）

- 定向检索：只针对缺口特征，不做全领域普查；
- 轮次限制：≤2 轮，每轮 1–3 条短查询，中英文各一轮；
- 证据编号：新增证据按 D3、D4… 顺延，**不得覆盖、替换或重排**原 D1、D2；
- 公开日核实：PDF 首页脚注 → 正文时间线 → 官方库；早于申请日/优先权日才可用于评述；
- 真实性：只使用能给出公开号/DOI/URL 的文献；无法核实即放弃，回到原证据体系；
- 检索无果：不得虚构证据，按原证据 + 公知常识/常规选择评述，并在工作说明中注明缺口。

## 补充检索配合要点（可选，仅在获准检索时适用）

二通撰写**默认不检索**，直接依据前次通知书的证据答复；仅当按「检索判定」确认需要补充检索且用户同意时，才适用以下要点。

### 论文公开时间的准确分析方法

当获取外文期刊论文作为对比文件时，必须按以下顺序核实公开时间：
1. **首先查看PDF首页下方脚注/页脚**：IEEE等期刊通常在首页脚注处标明"Date of Publication: XXXX"和"date of current version XXXX"，这是确定公开日的首要依据
2. **其次查看论文正文中的时间信息**：如"Manuscript received X; revised Y; accepted Z"，这些辅助判断
3. **最后交叉验证在线数据库**：如IEEE Xplore页面的Publication Date信息
4. **注意事项**：不要仅依赖Google Scholar等第三方数据库的年份信息，这些可能只显示年份而没有具体月份/日期

### 检索效率优化——提前终止机制

默认情形下不启动检索，本机制仅在获准补充检索后适用。在检索过程中，当发现特别相关的对比文件时，可以启动提前终止机制：
1. **提前终止条件**：当获取的对比文件与目标专利的核心技术特征重叠度超过80%，且公开时间可用时，可以暂停全面检索
2. **立即使用该对比文件进行创造性评述**：优先完成基于该核心对比文件的评述工作
3. **根据评述结果决定是否需要补充检索**：
   - 如果核心对比文件+D2/公知常识已足以评述所有权利要求，则检索任务基本完成
   - 如果评述中存在缺口（如核心对比文件缺少某关键特征），再有针对性地补充检索该缺口方向
4. **优势**：避免在已找到核心对比文件后继续大规模检索的资源浪费，提高审查效率

### 外文非专利文献的内容提取要点

对于外文期刊论文类对比文件，提取技术内容时应重点关注：
1. **公式/方程式**：这是论文公开技术特征的核心证据，需逐条记录
2. **算法伪代码或步骤描述**：通常在Section标题为"Proposed..."的章节中
3. **定义性语句**：如"we define...", "let...denote..."等，这些是特征比对的关键
4. **表格总结**：许多论文在表格中总结了算法步骤，需完整提取

## 工作流程

### Step 0: 检索判定（必须先做）

在阅读材料前先完成「检索判定」，并在答复正文之前输出工作说明块：

- 默认：`【检索判定】不检索` —— 依据前次通知书引用的对比文件（D1、D2…）与本申请说明书原文答复；
- 例外：`【检索判定】需补充检索（待确认）` —— 写明缺口所在、拟检索方向，并**等待用户确认**。

未输出检索判定的答复视为不合格。检索判定属于工作说明，不属于通知书正文。

### Step 1: 阅读材料并提取申请人意见要点

仔细阅读申请人意见陈述书，按以下维度提取要点：

1. **修改说明**：申请人做了哪些修改（合并权项、删除权项、适应性修改）
2. **对区别特征的争议点**：申请人认为哪些区别特征被错误认定
3. **对公知常识认定的异议**：申请人是否质疑审查员对"公知常识"的适用
4. **技术效果的主张**：申请人主张的技术效果及协同作用
5. **对从属权利要求的理由**：从属权利要求创造性的独立理由
6. **明显错误识别**：检查申请人意见中是否存在与本申请无关的内容（如复制粘贴错误）

**输出**：申请人意见要点摘要，按论点编号。

### Step 2: 规划答复策略

针对每个申请人论点，规划答复策略：

| 策略类型 | 适用场景 |
|---------|---------|
| **事实反驳** | 申请人论述与说明书/对比文件原文矛盾 |
| **技术原理反驳** | 申请人技术理解有误，混淆概念 |
| **公知常识论证** | 引用教科书/标准文献证明属于公知常识 |
| **技术启示论证** | 说明D1+D2/公知常识已给出充分技术启示 |
| **技术效果归因** | 将技术效果归因于已被公开的部分 |
| **接受（部分）** | 申请人意见合理，需调整评述（少见） |

**关键原则**：
- 优先使用申请人自己的说明书内容反驳其意见（最有力）
- 指出申请人"自我矛盾"是最有效的反驳方式
- 公知常识必须举具体例子（教科书、经典论文、标准协议）
- 保持客观、专业的审查员语气，不带情绪化表达

### Step 3: 撰写"答复申请人意见"部分

**格式模板**（严格遵循）：

```
申请人于XXXX年XX月XX日提交了意见陈述书和经过修改的申请文件，审查员在阅读了上述文件后，对本申请继续进行审查，再次提出如下审查意见。

**一、答复申请人意见**

申请人在意见陈述书中，陈述了本专利申请的权利要求1-X具有创造性的理由，审查员认真考虑了意见陈述书，不能接受申请人的观点。理由为：

1）申请人认为：
[概括申请人的核心观点，保持客观转述]

答复：审查员不能接受上述观点，理由如下：

[逐条给出反驳理由，使用"首先/其次/再次/最后"等连接词]

综上所述，申请人的论点X不具有说服力。

2）申请人认为：...
答复：...
...

综上所述，申请人的意见陈述不具有说服力。
```

**撰写要点**：
1. 转述申请人观点时要客观准确，不歪曲
2. 答复时首先直击要害（最强反驳点放前面）
3. 引用说明书原文需标注段落号【XXXX】
4. 引用对比文件原文需标注出处（参见第X页）
5. 如果申请人意见中存在与本申请无关的内容（复制粘贴错误），不予回应

### Step 4: 撰写"创造性评述"部分

在一通创造性评述基础上进行修改：

1. **权利要求编号调整**：对应申请人修改后的新权利要求编号
2. **权利要求内容调整**：反映申请人合并/修改后的权利要求内容
3. **区别特征重新归纳**：如申请人合并了权项，区别特征可能减少
4. **从属权利要求重新评述**：引用的权利要求编号需更新
5. **维持一通的核心结论**：D1仍为最接近现有技术，区别特征仍属于公知常识

**注意**：如果申请人的修改导致区别特征发生变化（如新增了原说明书中未评述的特征），先按「检索判定」处理：
- 原对比文件已公开该新增特征 → **无需检索**，直接在创造性评述中补引对应段落；
- 原对比文件未涉及该特征 → 属于"需补充检索"情形，先说明理由并取得用户同意；
- 未获用户同意 → 按公知常识/常规选择基于原证据评述，**不得虚构新证据**，并在工作说明块注明该缺口及处理方式。

**格式**：主要遵循「通知书撰写辅助」提示词（2026年10月版本）的权利要求评述格式规范；如用户提供了上一次／前一次审查意见通知书并说明沿用，则参照该通知书的实际格式。

### Step 5: 添加结尾模板

使用「通知书撰写辅助」提示词（2026年10月版本）中的标准结尾模板语段；如用户提供了上一次／前一次审查意见通知书并说明沿用，则以该通知书的结尾语段为准。

## 常见申请人论点及标准回应策略

### 类型A："区别特征未被公开"

申请人主张对比文件没有公开某个具体步骤/特征。

**标准回应**：
- 指出对比文件的上位概念已涵盖该特征
- 说明该具体步骤是本领域技术人员容易想到的常规选择
- 如果对比文件确实未公开，论证属于公知常识（举例说明）

### 类型B："公知常识适用过度"

申请人质疑审查员将具体技术方案简单归结为公知常识。

**标准回应**：
- 拆解申请人的"整体方案"为多个独立步骤
- 证明每一步都是公知常识（举教科书/标准文献例子）
- 指出组合这些步骤没有产生预料不到的技术效果
- 引用《审查指南》第二部分第四章第6.3节关于"公知常识"的规定

### 类型C："技术效果协同作用"

申请人主张多个区别特征协同产生意外技术效果。

**标准回应**：
- 分析技术效果的真正来源（通常来自频域处理，已被D1公开）
- 说明时域/后处理步骤不产生额外技术效果
- 论证"协同作用"缺乏技术依据

### 类型D："对比文件技术思路不同"

申请人主张对比文件的技术思路与本申请根本不同，没有技术启示。

**标准回应**：
- 找出对比文件与本申请共同的技术原理
- 指出申请人夸大了"思路差异"
- 论证本领域技术人员关注的是解决技术问题的具体手段，而非"思路"

## 格式规范

### 二通特有格式

1. 开头必须使用二通模板（含"申请人于XX年XX月XX日提交..."）
2. "一、答复申请人意见"使用加粗标题
3. 申请人观点和答复使用"1）申请人认为：... 答复：..."格式
4. "二、创造性评述"使用加粗标题
5. 后续评述遵循「通知书撰写辅助」提示词（2026年10月版本）的权利要求评述格式；或参照用户提供的上一次／前一次审查意见通知书格式

### 全文结构

```
【检索判定】不检索：本次答复仅依据前次通知书引用的 D1、D2 及本申请说明书原文。
（以上为工作说明，不属于通知书正文）
────────────────────────
[二通开头模板]

**一、答复申请人意见**

申请人在意见陈述书中...
1）申请人认为：...
答复：...
2）申请人认为：...
答复：...
...
综上所述，申请人的意见陈述不具有说服力。

**二、创造性评述**

[遵循「通知书撰写辅助」提示词（2026年10月版本）的权利要求评述格式；或参照用户提供的上一次／前一次审查意见通知书格式]
1.独立权利要求1...
2.权利要求2...
...
[结尾模板]
```

## 禁止事项

- 不回应申请人意见中与本申请明显无关的内容（如复制粘贴错误）
- 不使用情绪化语言或讽刺语气
- 不从属权利要求写完整三步法
- 不添加"总结""补充对比文件分析"等额外章节（「检索判定」「补充证据说明」属于工作说明，不视为额外章节，见下条）
- 公知常识不直接断言而不举例
- 不得在未获用户同意时自行检索，或引入未经确认的新对比文件
- 不得用补充检索结果替换前次通知书的证据体系（D1、D2 的编号与结论不得擅自推翻）
- 不得编造新证据的公开号、公开日或原文
- 「检索判定」「补充证据说明」必须置于通知书正文之前并标注"不属于通知书正文"；除此之外不得添加任何章节

# 常见申请人论点及标准回应

> 本文件列举了二通中申请人最常见的论点类型及审查员的标准回应策略，供撰写时参考。

---

## 类型A："区别特征未被D1/D2公开"

### 申请人典型表述

"对比文件1并未公开区别技术特征X中'...'这一特定的更新步骤/操作/限定。"
"对比文件1公开的是...，而本申请采用的是完全不同的..."

### 回应策略

**策略A1：上位概念已涵盖**

指出D1虽然未明确记载某具体步骤，但其上位概念或通用公式已涵盖该技术内容。

示例：
> D1的公式(4) ξ_k=λ_X(k)/λ_d(k)已完整定义了基于噪声方差λ_d的先验信噪比。本申请中"根据初始噪声方差生成先验信噪比"本质上是将该公式中的λ_d用初始估计值代入，属于该公式的直接应用。

**策略A2：具体参数选择是常规选择**

即使D1未公开某个具体参数或步骤，该参数/步骤本身属于本领域常规选择。

示例：
> "前40帧"仅是一个具体的数值选择。在语音增强领域，利用前若干帧（20帧、40帧、60帧等）作为静音段估计初始噪声方差是标准做法，例如经典的logMMSE算法和多种VAD方法均采用此方式。

**策略A3：属于公知常识（必须举例）**

引用教科书或经典文献证明该技术属于公知常识。

示例：
> WOLA（Weighted Overlap-Add）方法中，分析端和合成端均加窗是本领域的标准做法。在T. F. Quatieri所著《离散时间语音信号处理：原理与实践》等教科书中均有详细记载。

---

## 类型B："公知常识适用过度宽泛"

### 申请人典型表述

"审查员的这一认定存在对'公知常识'的过度宽泛适用。"
"《审查指南》规定，审查员引用公知常识应当确切，不能将具体的、包含了多个运算步骤的技术方案整体等同于一个宽泛的理论概念。"
"审查员并没有指出本领域中存在与本申请完全一致的..."

### 回应策略

**策略B1：拆解为独立步骤逐一论证**

将申请人主张的"整体方案"拆解为多个独立操作步骤，证明每一步都是公知常识。

示例：
> 申请人将时域波形重构步骤作为一个整体主张其非显而易见性，但审查员认为，该过程可以分解为以下独立步骤：（1）对逆变换后的时域信号加窗——WOLA标准操作；（2）相邻帧重叠部分相加——OLA核心步骤；（3）除以权系数进行归一化——WOLA标准补偿。每一步单独看都是本领域公知常识。

**策略B2：引用《审查指南》回应**

> 《审查指南》第二部分第四章第6.3节规定，审查员在审查意见通知书中引用的公知常识应当是确凿的。审查员认为，WOLA方法作为短时傅里叶变换信号重构的标准方法，其具体操作步骤在本领域教科书中已有详细记载，属于确凿的公知常识。

**策略B3：论证组合无意外效果**

> 将上述标准步骤组合在一起，并没有产生预料不到的技术效果。这些步骤的共同目的是将频域增强后的离散帧信号重构为连续时域信号，属于WOLA方法的完整标准流程。

---

## 类型C："技术效果协同作用"

### 申请人典型表述

"区别特征1-3协同作用才实现了...的技术效果"
"区别特征1在频域提供了...，而区别特征2和3在时域提供了...，两者结合才实现了..."
"上述技术效果的协同作用是对比文件1结合公知常识所无法轻易得出的"

### 回应策略

**策略C1：技术效果归因分析**

分析技术效果的真正来源，指出其来自已被D1公开的部分。

示例：
> 申请人声称区别特征1-3协同作用实现"加大降噪深度20dB以上"的技术效果，但审查员认为，该降噪效果主要来源于频域的修正系统函数（对应D1中已公开的改进最佳增益函数G(ξ_k,γ_k) = G_H1(ξ_k,γ_k)^{p_k} · G_min^{1-p_k}，参见D1第201页），而非时域的重叠相加操作。时域的加窗、重叠相加和归一化处理仅是将频域增强后的信号转换回连续时域信号的标准后处理流程，其本身不产生额外的降噪效果。

**策略C2：论证无协同机制**

> 频域处理（区别特征1）与时域重构（区别特征2、3）之间不存在技术协同机制。时域重构步骤仅是对频域处理结果的逆变换和波形重建，不改变频域的增强效果，两者是串联关系而非协同关系。

---

## 类型D："对比文件技术思路根本不同"

### 申请人典型表述

"对比文件1的先验信噪比更新高度依赖于'前一帧的信号估计状态'，而本申请..."
"对比文件1全文未公开也未暗示放弃...，转而采用本申请这种..."
"本领域技术人员在面对对比文件1时，没有技术启示去做出这种根本性算法逻辑的替换"

### 回应策略

**策略D1：说明书自我矛盾法（最有力）**

找出申请人意见与说明书公开内容的矛盾。

示例：
> 申请人主张本申请"彻底脱离了对前一帧增强语音的递归依赖"，但本申请说明书【0117】段明确记载"可用判决引导法由前后帧数据迭代得到"，【0118】段进一步记载了使用平滑系数进行迭代更新。上述记载清楚地表明，本申请的先验信噪比更新仍然依赖于前一帧信息。申请人一方面声称"彻底脱离递归依赖"，另一方面说明书中明确使用了递归迭代机制，两者存在根本性矛盾。

**策略D2：技术原理相通**

> D1的非因果先验信噪比估计方法与本申请都利用了噪声方差和信噪比的基本关系来计算增强参数，两者的技术原理是相通的。虽然具体实现路径有所不同，但本领域技术人员在面对"如何初始化信噪比"这一问题时，容易想到利用初始噪声方差代入信噪比计算公式的方式。

**策略D3：关注解决手段而非"思路"**

> 创造性判断应关注具体技术手段的组合是否显而易见，而非抽象的"技术思路"。本领域技术人员在解决具体技术问题时，会综合考虑现有技术中公开的各种手段，而非被所谓"思路"所束缚。

---

## 类型E："特定操作步骤具有创造性"

### 申请人典型表述

"本申请明确限定了...这一特定操作时序"
"本申请设计了包含严密时序的波形重构步骤"
"审查员仅仅指出了...这一理论大方向，并没有指出..."

### 回应策略

**策略E1：步骤是标准流程的一部分**

> "将中间序列的前半序列与上一帧中间序列的后半序列相加"正是50%重叠条件下OLA操作的标准描述。在OLA框架中，由于相邻帧之间存在重叠区域，后一帧的重叠部分需要与前一帧对应的重叠部分相加才能重建连续的时域信号，这是OLA方法的核心操作步骤。

**策略E2：参数是常规选择**

> 汉宁窗的平方和归一化是满足Princen-Bradley完美重构条件的标准理论结果，使用50%重叠也是WOLA中最常见的参数设置。选择汉宁窗和50%重叠均为本领域技术人员的常规选择。

---

## 类型F：从属权利要求的独立创造性

### 申请人典型表述

"修改后的权利要求2-5为修改后的权利要求1所对应的从属权利要求，基于与修改后的权利要求1基本相同的理由，修改后的权利要求2-5也具备创造性"

### 回应策略

> 权利要求2-5为权利要求1的从属权利要求，在权利要求1不具备创造性的基础上，权利要求2-5的附加技术特征或者被D1公开（参见...），或者属于本领域公知常识（例如...），因此权利要求2-5也不具备创造性。

## 特殊情形处理

### 情形S1：申请人意见中包含明显错误

申请人意见陈述书中可能包含与其他案件混淆的内容（如复制粘贴错误，提到AGC、ADC、PID等与本申请完全无关的技术）。

**处理**：不予回应。二通中只回应与本申请技术方案相关的实质性论点。

### 情形S2：申请人意见有部分合理之处

如果申请人的某些论点确实指出了审查意见的不足（如某个特征确实未被D1公开，但属于公知常识）。

**处理**：接受合理部分，调整评述策略（如增加公知常识论证），但仍维持不具备创造性的结论。

## 完整示例

以下为一个完整的二通格式示例（内容简化）：

```
申请人于2026年6月29日提交了意见陈述书和经过修改的申请文件，审查员在阅读了上述文件后，对本申请继续进行审查，再次提出如下审查意见。

**一、答复申请人意见**

申请人在意见陈述书中，陈述了本专利申请的权利要求1-8具有创造性的理由，审查员认真考虑了意见陈述书，不能接受申请人的观点。理由为：

1）申请人认为：对比文件1并未公开"获取前40帧计算初始噪声方差"这一特定步骤，且本申请的机制"彻底脱离了对前一帧增强语音的递归依赖"。

答复：审查员不能接受上述观点，理由如下：

首先，申请人关于本申请"彻底脱离递归依赖"的论述与说明书公开的内容相矛盾。本申请说明书【0117】段明确记载"可用判决引导法由前后帧数据迭代得到"，【0118】段进一步记载了使用平滑系数进行迭代更新。

其次，D1的公式(4)(5)已完整定义了基于噪声方差的先验和后验信噪比，"获取前40帧计算初始噪声方差"属于利用静音段估计噪声的常规手段。

综上所述，申请人的论点1不具有说服力。

2）申请人认为：审查员对"公知常识"过度宽泛适用，两次加汉宁窗及特定重叠相加操作不是普通OLA。

答复：审查员不能接受上述观点，理由如下：

首先，WOLA方法中分析端和合成端均加窗是本领域标准做法。

其次，"前半序列与上一帧后半序列相加"是50%重叠条件下OLA操作的标准描述。

再次，除以预设权系数是WOLA归一化标准步骤。

最后，申请人声称的"加大降噪深度20dB以上"的技术效果主要来自频域修正系统函数（D1已公开），时域操作不产生额外降噪。

综上所述，申请人的论点2不具有说服力。

3）申请人认为：修改后的权利要求2-5、6-8基于与权利要求1基本相同的理由具备创造性。

答复：审查员认为，在权利要求1不具备创造性的基础上，权利要求2-5的附加技术特征或者被D1公开，或者属于本领域公知常识；权利要求6-8分别对应方法权利要求的装置/设备/存储介质形式，同样不具备创造性。具体评述参见本通知书第二部分。

综上所述，申请人的意见陈述不具有说服力。

**二、创造性评述**

1.独立权利要求1请求保护一种[技术主题]...
[完整三步法评述，参照「通知书撰写辅助」提示词（2026年10月版本）格式]

[简评]

基于上述理由，本申请的独立权利要求以及从属权利要求都不具备创造性...
```
