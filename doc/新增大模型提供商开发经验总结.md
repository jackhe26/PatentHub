# 新增大模型提供商开发经验总结

## 开发时间
2026年7月4日

## 开发目标
在 PatentHub 中新增默认大模型提供商（以 Moonshot/Kimi 为例），使其出现在设置 → 模型提供方列表中，用户可以直接选择并配置使用。

---

## 核心原理

PatentHub 使用 **Provider Registry（提供商注册表）** 机制管理所有大模型提供商。添加新提供商的本质是：

1. 在注册表中注册一个 Provider 定义
2. 提供该提供商的图标、默认配置、模型列表
3. 告诉 UI 在哪里显示该提供商

## 详细步骤

### Step 1: 添加枚举值

**文件**: `src/shared/types/provider.ts`

在 `ModelProviderEnum` 中添加新的枚举值：

```typescript
export enum ModelProviderEnum {
  // ... 已有枚举
  Moonshot = 'moonshot',
  // ...
}
```

> ⚠️ **枚举值必须唯一**，建议使用小写 + 连字符格式（如 `'moonshot'`）。

---

### Step 2: 创建 Provider 定义文件

**文件**: `src/shared/providers/definitions/{provider}.ts`（新建）

这是最关键的一步，定义提供商的所有核心信息：

```typescript
import { ModelProviderEnum, ModelProviderType } from '../../types'
import { defineProvider } from '../registry'
import OpenAI from './models/openai'  // 大多数国产模型都是 OpenAI 兼容

export const moonshotProvider = defineProvider({
  id: ModelProviderEnum.Moonshot,     // 枚举值
  name: 'Moonshot (Kimi)',            // 显示名称
  type: ModelProviderType.OpenAI,     // API 类型（OpenAI 兼容直接复用 OpenAI 类）
  urls: {
    website: 'https://www.moonshot.cn',
    docs: 'https://platform.moonshot.cn/docs',
    apiKey: 'https://platform.moonshot.cn/console/api-keys',
  },
  defaultSettings: {
    apiHost: 'https://api.moonshot.cn',  // API 基础地址
    models: [
      {
        modelId: 'kimi-k2.6',
        capabilities: ['reasoning', 'tool_use'],
        contextWindow: 256_000,
      },
      // ... 更多模型
    ],
  },
  createModel: (config) => {
    return new OpenAI(
      {
        apiKey: config.providerSetting.apiKey || '',
        apiHost: config.formattedApiHost,
        model: config.model,
        dalleStyle: config.settings.dalleStyle || 'vivid',
        temperature: config.settings.temperature,
        topP: config.settings.topP,
        maxOutputTokens: config.settings.maxTokens,
        injectDefaultMetadata: config.globalSettings.injectDefaultMetadata,
        useProxy: false,
        stream: config.settings.stream,
      },
      config.dependencies
    )
  },
  getDisplayName: (modelId, providerSettings) => {
    return `Moonshot API (${providerSettings?.models?.find((m) => m.modelId === modelId)?.nickname || modelId})`
  },
})
```

#### Provider 配置字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | `string` | ✅ | 唯一标识，与枚举值一致 |
| `name` | `string` | ✅ | 显示名称 |
| `type` | `ModelProviderType` | ✅ | API 协议类型，大多数国产模型用 `OpenAI` |
| `urls` | `object` | ❌ | 官网、文档、API Key 页面 |
| `defaultSettings` | `object` | ❌ | 默认配置 |
| `defaultSettings.apiHost` | `string` | ❌ | API 基础地址 |
| `defaultSettings.models` | `array` | ❌ | 默认模型列表 |
| `createModel` | `function` | ✅ | 工厂函数，创建模型实例 |
| `getDisplayName` | `function` | ❌ | 获取模型显示名称 |

#### 模型配置字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `modelId` | `string` | 调用 API 时使用的模型 ID |
| `contextWindow` | `number` | 上下文窗口大小（token 数）|
| `capabilities` | `string[]` | 能力标签：`'chat'`、`'vision'`、`'tool_use'`、`'reasoning'`、`'image'` |
| `type` | `string` | 模型类型：`'chat'`（默认）、`'embedding'`、`'rerank'` |
| `nickname` | `string` | 显示别名（可选）|

### Step 6: 设置列表图标回退（通用修复）

**文件**: `src/renderer/components/settings/provider/ProviderList.tsx`

> ⚠️ 这是一个**通用修复**，只需做一次，后续添加新提供商自动生效。

设置页面通过 `import.meta.glob` 加载 `src/renderer/static/icons/providers/*.png` 图片。如果没有对应的 PNG 文件，图标位置会显示空白。

**修复方式**：找不到 PNG 时回退到 `ProviderIcon` SVG 组件：

```tsx
import ProviderIcon from '@/components/icons/ProviderIcon'

// 在 Provider 列表渲染中：
icons.find((icon) => icon.name === provider.id)?.src ? (
  <Image w={32} h={32} src={...} alt={provider.name} />
) : (
  <ProviderIcon provider={provider.id} size={32} />
)
```

---

## 两种图标方案对比

| 方案 | 文件位置 | 优点 | 缺点 |
|------|---------|------|------|
| **PNG 图片** | `src/renderer/static/icons/providers/{id}.png` | 设置列表原生支持 | 需要额外文件，多尺寸适配 |
| **SVG 内联** | `src/renderer/components/icons/ProviderIcon.tsx` | 矢量无限缩放，代码内联 | 需要修改 ProviderList 回退逻辑 |

> 💡 **推荐**：同时提供两种，PNG 优先，SVG 作为回退。

## OpenAI 兼容 vs 非兼容

### OpenAI 兼容（大多数国产模型）

直接使用现有的 `OpenAI` 模型类，无需新建模型类：

```typescript
import OpenAI from './models/openai'

createModel: (config) => {
  return new OpenAI({ ... }, config.dependencies)
}
```

**已知 OpenAI 兼容的国产提供商**：
- DeepSeek、Moonshot、SiliconFlow、ChatGLM、VolcEngine、OpenRouter

### 非 OpenAI 兼容

需要新建模型类，继承 `AbstractAISDKModel`：

```
src/shared/providers/definitions/models/{provider}.ts
```

并自行实现：
- `getProvider()` - 返回 AI SDK Provider
- `getChatModel()` - 返回 LanguageModelV3
- `getCallSettings()` - 返回调用参数

示例参考：`src/shared/providers/definitions/models/gemini.ts`、`claude.ts`

## 常见问题

### Q1: 设置页面看不到图标？
**原因**: ProviderList 只加载 PNG，没有对应的 PNG 文件。  
**解决**: 按 Step 6 添加 SVG 回退逻辑，或提供 PNG 文件。

### Q2: 模型能力标签有什么用？
- `'vision'` → 支持图片输入
- `'tool_use'` → 支持工具调用（联网、知识库等）
- `'reasoning'` → 支持深度思考（显示推理过程）
- `'image'` → 支持图片生成

UI 会根据这些标签显示对应的能力图标。

### Q3: 导入顺序影响什么？
Provider 注册表使用 `Map`，按导入顺序插入。导入越早，在 UI 列表中越靠前。建议按重要程度排序。

### Q4: 如何验证是否成功？
1. 重新编译项目
2. 打开设置 → 模型提供方
3. 检查新提供商是否出现在列表中
4. 检查图标是否正常显示
5. 点击提供商，检查默认模型列表是否正确
6. 输入 API Key 测试对话

## 三个国产大模型接入实战记录

本次批量接入了三个国产大模型：

| 提供商 | ID | API Host | 图标 | 状态 |
|--------|-----|----------|------|------|
| **Moonshot (Kimi)** | `moonshot` | `https://api.moonshot.cn` | SVG 内联 | ✅ |
| **MiniMax** | `minimax` | `https://api.minimaxi.com` | PNG | ✅ |
| **Zhipu（智谱）** | `zhipu` | `https://open.bigmodel.cn/api/paas/v4` | PNG | ✅ |

### Moonshot 特殊点
- 只有 SVG 图标，没有 PNG → 需要修改 `ProviderList.tsx` 添加 SVG 回退逻辑
- 模型：`kimi-k2.6`, `kimi-k2.7-code`, `kimi-k2.7-code-highspeed`

### MiniMax 特殊点
- PNG 图标已存在，接入最简洁（只需改 4 个文件）
- 模型：`MiniMax-M3`, `MiniMax-M2.7`, `MiniMax-M2.7-highspeed`

### Zhipu 特殊点（踩坑记录）
- **API Host 路径问题**（重点！）
  - 智谱 API Host 为 `https://open.bigmodel.cn/api/paas/v4`，**不是标准 `/v1` 路径**
  - `normalizeOpenAIApiHostAndPath` 在看不到 `apiPath` 时会自动追加 `/v1`，导致 URL 变为 `.../v4/v1/chat/completions`（404）
  - **修复**：需要修改 `OpenAI` 模型类，让它能接收 `apiPath` 参数

```typescript
// src/shared/providers/definitions/models/openai.ts
interface Options {
  apiKey: string
  apiHost: string
  apiPath?: string  // 新增
  // ...
}

// src/shared/providers/definitions/zhipu.ts
defaultSettings: {
  apiHost: 'https://open.bigmodel.cn/api/paas/v4',
  apiPath: '/chat/completions',  // 显式指定
  // ...
}

createModel: (config) => {
  return new OpenAI({
    apiHost: config.formattedApiHost,
    apiPath: config.formattedApiPath,  // 传递 apiPath
    // ...
  })
}
```

## 新增常见问题

### Q5: 为什么连接测试报 404，`/v4/v1/chat/completions`？
**原因**: `normalizeOpenAIApiHostAndPath` 函数在 `apiHost` 不以 `/v1` 结尾且没有 `apiPath` 时，会自动追加 `/v1`。  
**解决**: 在 Provider 定义中显式设置 `apiPath: '/chat/completions'`，并修改 `OpenAI` 模型类接收 `apiPath` 参数。

### Q6: 如何判断是否需要设置 apiPath？
| API Host 特征 | 是否需要 apiPath | 示例 |
|--------------|-----------------|------|
| 标准 OpenAI 格式（以 `/v1` 结尾） | ❌ 不需要 | `https://api.openai.com` |
| 自定义路径（不以 `/v1` 结尾） | ✅ 需要 | `https://open.bigmodel.cn/api/paas/v4` |
| 已包含完整路径 | ❌ 不需要 | `https://api.mistral.ai/v1` |

## 经验总结

1. **大多数国产模型都是 OpenAI 兼容**，接入成本低，直接复用 `OpenAI` 类
2. **图标需要双重保障**：SVG 内联 + PNG 文件，或修改 ProviderList 添加回退逻辑
3. **capabilities 标签影响 UI 展示**，正确标注可以显示模型能力图标
4. **导入顺序 = UI 显示顺序**，合理安排优先级
5. **枚举值、文件名、icon name 三者保持一致**（都用 `moonshot`），避免找不到图标
6. **非标准 API 路径必须显式设置 apiPath**，否则 normalize 函数会自动追加 `/v1` 导致 404
7. **OpenAI 模型类需要能接收 apiPath**，否则 Provider 定义中的 apiPath 不会被传递
8. **图像生成模型用 `capabilities: ['image']`**，不能用 `type: 'image'`（schema 不支持）
