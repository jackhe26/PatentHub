## 二、问题 1：Agent 页面没有窗口按钮（也不能拖拽）

### 2.1 排查过程（证据链）

不靠常识猜，按「谁提供按钮 → 谁没挂载它」的顺序查：

| 步骤 | 位置 / 命令 | 结论 |
|------|-------------|------|
| ① 窗口是不是无边框？ | `src/main/main.ts:306-312` | 是。`frame: false` + `titleBarStyle: 'hidden'`，**系统原生按钮已被移除**，必须由渲染层自绘 |
| ② 自绘按钮在哪？ | grep `WindowControls` | 只有 `src/renderer/components/layout/WindowControls.tsx` 一个实现 |
| ③ 谁在用它？ | 同一 grep | 只有 `components/layout/Header.tsx`（会话页）与 `components/layout/Page.tsx`（首页/关于/审查搭档/图片生成/设置…） |
| ④ Agent 页面走页壳了吗？ | `routes/__root.tsx:180-188` | **没有**。`/agents`、`/agent-chat/:id` 由 `useLocation()` 直接渲染 `<AgentsPage/>`、`<AgentChatPage/>`，绕开了 Header/Page |
| ⑤ 为什么连拖拽也不行？ | `src/renderer/static/index.css:46-55` | `#root` 是 `drag`，但 `.App`（Agent 页面外层容器）被设为 `no-drag`，而 Agent 页面里**没有任何 `.title-bar` 元素** → 整页无拖拽区 |

### 2.2 根本原因

**窗口三键 + 拖拽区属于「页面壳」的职责**，项目把它收敛在两个页壳组件里：

- `components/layout/Header.tsx`：会话页专用（Session 名 + Toolbar + WindowControls）
- `components/layout/Page.tsx`：通用页壳（侧边栏按钮 + 标题 + `right` 插槽 + WindowControls，根元素 `<Flex h={54} className="title-bar">`）

Agent 模块是为快速跑通而新增的独立页面，作者直接用自己的 `<Group h={54}>` / `<Box p="md">` 铺内容，**既没挂 `WindowControls`，也没有 `.title-bar` 类**，于是同时丢了「窗口三键」和「窗口拖拽」，附带还丢了「侧边栏折叠按钮」。

> 这是一类**结构性回归**：只要新页面不走页壳，无边框窗口的窗口操作能力就会整体消失。此前的教训文档（`2026-06-11-Header拖拽与搭档选择器位置优化开发总结.md`）也是同一主题。

### 2.3 修复方案（复用页壳，不新造轮子）

**① `src/renderer/agents/pages/AgentsPage.tsx`** —— 套用标准页壳，标题与「新建 Agent」按钮上移到标题栏：

```tsx
// 修复前
return (
  <Box p="md">
    <Group justify="space-between" mb="lg">
      <Title order={2}>🤖 Agents 管理</Title>
      <Button leftSection={<IconPlus size={16} />} onClick={handleCreate}>新建 Agent</Button>
    </Group>
    ...

// 修复后
return (
  <Page
    title="🤖 Agents 管理"
    right={
      <Button size="sm" leftSection={<IconPlus size={16} />} onClick={handleCreate}>
        新建 Agent
      </Button>
    }
  >
    <Box p="md">
      ...
```

**② `src/renderer/agents/pages/AgentFormPage.tsx`** —— 同样套 `Page`，页面内保留「返回」按钮（原 `<Title order={3}>` 删除，标题已在标题栏）：

```tsx
<Page title={isEdit ? '编辑 Agent' : '新建 Agent'}>
  <Box p="md" style={{ maxWidth: 1200, margin: '0 auto' }}>
    <Group mb="lg">
      <Button variant="light" leftSection={<IconArrowLeft size={16} />} onClick={...}>返回</Button>
    </Group>
    ...
```

**③ `src/renderer/agents/pages/AgentChatPage.tsx`** —— 对话页是自定义满屏布局（`<Stack h="100vh">`），不适合整体塞进 `Page`，只给它自己的表头补上拖拽区与窗口按钮：

```tsx
<Group
  h={54} px="md" gap="md" wrap="nowrap"
  className="title-bar flex-none"                        // ← 拖拽区
  style={{ borderBottom: '1px solid var(--mantine-color-gray-3)' }}
>
  <ActionIcon variant="subtle" onClick={...}><IconArrowLeft size={20} /></ActionIcon>
  <Text size="xl">{agent.icon}</Text>
  <Stack gap={0}>{/* Agent 名 + 徽章 */}</Stack>
  <WindowControls className="ml-auto" />                 // ← 最小化 / 最大化 / 关闭
</Group>
```

> `.title-bar` 内部的 `button` / `[role="button"]` / `.controls` 会被 `index.css` 自动标记为 `no-drag`，按钮点击不受拖拽影响 —— 与会话页 `Header` 的做法完全一致。

### 2.4 修复结果

- `/agents`、`/agent-chat/:id`、新建/编辑 Agent 表单页**右上角均出现 `— □ ✕`**；
- 三个页面的标题栏空白处**可拖拽移动窗口**；
- `/agents`、表单页额外恢复「侧边栏折叠按钮」（`Page` 自带）。

## 三、问题 2：添加附件「文件类型是空白 / 没有对应图标」

### 3.1 先排除「假嫌疑」——把"没有图标"变成可验证的事实

「图标空白」可能由 4 类原因造成，逐条用**可执行命令**验证，避免凭直觉改代码：

| 嫌疑 | 验证方式 | 结论 |
|------|----------|------|
| ① 图标资源文件缺失 | 列目录 + 逐个 `Test-Path`（26 个 `icons8-*.png` 与 WPS 三件套） | ✅ 全部存在 |
| ② 图标是"白图/纯透明"（看上去像空白） | 用 `sharp` 逐张输出通道均值：`stats().channels.map(c=>c.mean)` | ✅ 均有实际色彩（例：`icons8-pdf-48.png` → `[228,44,50,245]`），排除空白图 |
| ③ dev server 没把图片服务出去 | `Invoke-WebRequest http://localhost:1212/static/icons/icons8-pdf-48.png` | ✅ `200 image/png`，1176 bytes |
| ④ 组件导出不存在（`undefined` 会导致 React 抛错 → 整块区域空白） | `node -e` 逐个检查 `@tabler/icons-react` 的 25 个导出 | ✅ 全部为 `true` |
| ⑤ 附件根本没解析成功 | 应用日志 `main.log` | ✅ PDF 解析成功（见第一节旁证） |

> ⚠️ 踩坑记录：dev server（electron-vite）的**根目录是 `src/renderer`**，所以静态资源 URL 是 `/static/icons/xxx.png`；写成 `/src/renderer/static/icons/xxx.png` 会命中 SPA 兜底，返回 `200 text/html` 的 **index.html**（长度与首页一致），很容易误判成"资源 404"。

排除资源问题后，结论是**UI 呈现层与文件对话框白名单**两处独立缺陷。

### 3.2 缺陷 A：附件卡片只画「通用文档图标」，且完全没有类型信息

**原实现**（`src/renderer/agents/components/AttachmentBar.tsx`）：非图片一律渲染同一个通用图标，且只有文件名：

```tsx
{att.status === 'parsing' ? <Loader size="xs" />
  : att.isImage ? <IconPhoto size={22} stroke={1.5} />
  : <IconFileText size={22} stroke={1.5} />}        // ← 所有文档都是同一个通用图标
...
<Text size="xs" truncate>{att.name}</Text>          // ← 只有文件名，没有类型/大小
```

**对比**：项目其它地方的附件卡片（`FileMiniCard` / `MessageAttachment`）都是「**按扩展名的专属图标** + `类型 · 大小` 副标题」。所以附加 PDF/Word 时，用户看到的正是"没有对应图标、类型空白"。

**修复**：改用项目已有组件 `FileIcon`（`src/renderer/components/FileIcon.tsx`，按扩展名映射 PDF/Word/Excel/PPT/CSV/**WPS 三件套**/各类代码图标），并补上副标题：

```tsx
{attachments.map((att) => {
  const typeLabel = getFileTypeLabel(att.name, att.mime)   // PDF / DOCX / WPS ...
  const sizeLabel = formatFileSize(att.size)               // 1.24 MB
  const subtitle = [typeLabel, sizeLabel].filter(Boolean).join(' · ')
  return (
    <Box key={att.id} ...>
      ...
      ) : (
        <FileIcon filename={att.name} className="w-8 h-8" />   {/* 专属图标 */}
      )}
      <Tooltip label={...}><Text size="xs" truncate>{att.name}</Text></Tooltip>
      {subtitle && <Text c="dimmed" style={{ fontSize: 10 }}>{subtitle}</Text>}  {/* 类型 · 大小 */}
```

**同一问题也存在于消息气泡**：`AgentChatPage` 里附件原先用 emoji 显示 —— `<Badge>📎 {a.name}</Badge>`。emoji 在部分系统/字体下会渲染成空白或豆腐块，已改为 `leftSection={<FileIcon filename={a.name} className="w-3 h-3" />}`，保证图标一定可见。

### 3.3 缺陷 B：「添加附件」的文件对话框被过滤成空列表

**原实现**（`src/renderer/agents/services/attachmentPreprocess.ts`）是**手写硬编码短列表**：

```ts
export const AGENT_ATTACHMENT_ACCEPT =
  '.png,.jpg,.jpeg,.gif,.webp,.bmp,.svg,' +
  '.pdf,.doc,.docx,.ppt,.pptx,.xls,.xlsx,' +
  '.txt,.md,.csv,.json,.html,.xml,.log'
```

**根因**：`<input type="file" accept="...">` 会把**不匹配的文件从文件对话框中直接隐藏**。而该列表**缺少 README v1.3.6 明确支持的 WPS 与旧版 Office 格式**（`.wps` / `.et` / `.dps`），也缺少 `.odt/.ods/.odp/.mdx/.yaml` 等。用户工作目录里若以 WPS 文件为主，点「添加附件」时看到的几乎是**空列表** —— 与"文件类型是空白"的现象吻合。

**修复**：不再手写，改为复用项目权威类型表 `@shared/file-extensions`：

```ts
import { allSupportedExts } from '@shared/file-extensions'

export const AGENT_ATTACHMENT_ACCEPT = Array.from(
  new Set([
    // 图片：Agent 附件按钮同时支持图片（主程序的图片上传是独立入口，故此处单独补充）
    '.png', '.jpg', '.jpeg', '.gif', '.webp', '.bmp', '.svg',
    // 文档 / 文本 / 代码：与「设置 → 文档解析」支持的格式保持一致
    ...allSupportedExts,
  ])
).join(',')
```

**实测**：扩展名数量 **113**，含 `.wps/.et/.dps`、`.pdf`、`.docx`、`.md`（与主程序 `getFileAcceptString()` 同源）。

### 3.4 附带调整（DRY）

`src/renderer/components/InputBox/Attachments.tsx` 中已有的 `formatFileSize` / `getFileTypeLabel` 增加 `export`（**仅 +2/-2 行**），供 Agent 附件卡片复用，避免第三次重复实现。

## 六、经验教训（本次最有价值的部分）

### 6.1 关于「页面缺 UI 元素」类问题

- **功能性 UI（窗口三键、拖拽区、侧边栏按钮）属于"页面壳"的职责，不属于页面本身。** 新建页面时先问一句：**"它走的是哪个布局壳（`Page` / `Header` / 裸 `<div>`）？"** 在 Electron 无边框窗口下，绕过壳 = 直接丢掉窗口操作能力。
- **这类问题在开发机上看"页面能正常显示"完全发现不了**，只有真正想最小化/关窗/拖窗时才暴露 → 所以新页面必须走查"窗口三件套"。
- **同类问题会换页面复发**：2026-06-11 的教训是「`Toolbar` 容器误加 `controls` 类导致拖拽失效」，本次是「新页面没挂 `.title-bar` / `WindowControls`」。→ 建议把「拖拽区 + 窗口三键 + 侧边栏按钮」收敛为唯一入口（`Page`），并在新页面 checklist 里加一条硬性检查项。

### 6.2 关于「空白 / 没有图标」类问题：先用工具证伪资源层，再改 UI

本次把「图标空白」拆成 5 个可执行验证项（资源存在？像素非空？HTTP 200 且 `Content-Type` 正确？组件导出非 `undefined`？数据链路通？）逐一跑命令排除，结论是 **"资源全都正常，缺陷在 UI 呈现与 accept 白名单"**，从而直接锁定方向，避免"改颜色 / 换 emoji / 调大小"式的无效试错。

另外：**emoji 不是图标**。`📎`、`🤖` 这类字符依赖系统字体，在部分系统/字体下会渲染成空白或豆腐块；UI 中表示"文件/文档"应使用项目自己的 `FileIcon`（打包的 PNG 或矢量图标）。

### 6.3 关于「文件被过滤 / 看不到文件」类问题：白名单必须单一来源

- 任何 `accept` / 后缀白名单**必须复用权威源**（本项目是 `src/shared/file-extensions.ts`），手写副本一定会与主程序漂移。本次手写的副本恰好漏掉 `.wps/.et/.dps`（**恰是专利审查场景最常用的格式**），后果是"文件对话框看起来是空的"。
- 排查提示：当用户说"文件列表是空的 / 类型空白"时，**第一反应查 `accept`（文件对话框过滤器）**，而不是查图标。

### 6.4 关于工程环境（两个本次实打实踩到的坑）

| 坑 | 现象 | 处理方式 |
|---|---|---|
| 仓库存在 **CRLF / LF 混合** | 多行文本替换"明明看着一样却匹配不到" | 先规范化换行为 LF 再编辑（命令见第七节「规范化 CRLF → LF」）；改完统一 `pnpm exec biome format --write` |
| electron-vite dev server **根目录是 `src/renderer`** | 用 `/src/renderer/static/icons/x.png` 访问图片得到 `200 text/html`（SPA 兜底 index.html，长度=首页），极易误判成"资源 404" | 正确 URL 是 `/static/icons/x.png`；**判断资源是否存在要看 `Content-Type`，不能只看状态码** |

### 6.5 关于验证手法（三条可复用经验）

1. **HMR 日志** = 最便宜的"编译通过"证据（出现 `hmr update` 即无编译错误）；
2. **从 dev server 拉模块断言关键字符串** = 没有截图时证明"运行中的应用确实加载了新代码"的最强证据（比"我改完了"可靠得多）；
3. **测试基线对比**（`tsc` 错误数 173 → 173）= 在"仓库本来就不干净"的项目里，唯一能声明"我没有引入新错误"的方法。

最后交付给用户**3 步走查清单**，让对方 30 秒内自证，而不是让对方自己去猜哪里变了。

### 6.6 沟通层面

用户描述含口语/语音识别误差（"关闭案例" → "关闭**按钮**"）。正确做法：**先把口语拆解成可判定的技术断言**（"无边框窗口下，最小化按钮由谁渲染？"），再去 grep 代码逐条验证；不要在原话措辞上纠结，也不要在没有证据时"猜一个"就直接改代码 —— 本次第 2 个问题就有两种合理理解（图标不显示 / 文件被过滤），**两种都查、两种都修**，比赌一种更稳。
